# WhisperAnnote — Техническое задание (ТЗ)

**Дата:** 2026-06-01
**Версия:** 2.1
**Статус:** Проектирование

> **Ревизия 2.1 (по результатам архитектурного ревью).** Ключевые изменения относительно 2.0:
> только GPU (CUDA) в v2; отказ от ручного чанкинга (нативная обработка faster-whisper);
> HF-токен вводится в интерфейсе; усилена безопасность локального backend; промежуточные
> файлы выносятся в системный temp; один GPU-задача одновременно; max-overlap сопоставление
> спикеров; переименование спикеров в UI; виртуализация списка сегментов; управление загрузкой
> моделей. Подробности — в соответствующих разделах.

---

## 1. Наименование продукта

**WhisperAnnote 2.0** — десктопное приложение для автоматической транскрибации русскоязычных аудиозаписей совещаний с диаризацией спикеров.

---

## 2. Цель разработки

Создать замену устаревшему PyQt5-приложению WhisperAnnote 1.x (на базе Whisperer_GUI), объединив лучшие наработки трёх проектов:
- Whisperer_v1 (React-интерфейс, i18n)
- Whisperer_GUI + WhisperAnnote 1.x (пайплайн транскрибации + диаризации)
- WhisperLiveKit (FastAPI-архитектура, VAD)

Новая версия должна предоставлять современный интерфейс на Electron, поддерживать автоматическую пакетную обработку файлов из указанной папки и ориентироваться на русский язык.

---

## 3. Область применения

Транскрибация и диаризация записей:
- Рабочих совещаний и meeting-записей
- Интервью и подкастов
- Конференций и лекций
- Телефонных разговоров (колл-центры)

## 6. Архитектурные решения

### 6.1 Общая архитектура: трёхпроцессная модель

```
┌──────────────────────┐     IPC      ┌───────────────────────┐
│ Electron Main        │◄────────────►│ Electron Renderer     │
│ - Python manager     │              │ - React 18            │
│ - File watcher       │              │ - shadcn/ui           │
│ - Scheduler          │              │ - Tailwind            │
└──────────┬───────────┘              └───────────┬───────────┘
           │ child_process.spawn                  │ HTTP + WS
           │ (+ secret token, env: HF_TOKEN)      │ (+ Authorization: secret)
           ▼                                      ▼
┌──────────────────────────────────────────────────────────┐
│ Python FastAPI Backend (subprocess, 127.0.0.1)            │
│ - Auth middleware (shared secret) + CORS (electron origin)│
│ - /api/transcribe  (разовая обработка)                    │
│ - /api/queue       (пакетная очередь, concurrency=1)      │
│ - /api/models      (список + загрузка с прогрессом)       │
│ - /ws/progress     (прогресс в реальном времени)          │
│ - /api/health      (статус + GPU)                         │
└──────────────────────────────────────────────────────────┘
```

### 6.2 Конвейер обработки

```
Входной файл (.mp4, .mp3, .wav, ...)
  → [1] ffmpeg: конвертация в MP3 128kbps        (в системный temp)
  → [2] ffmpeg: извлечение WAV 16kHz mono PCM     (в системный temp)
  → [3] pyannote: диаризация по полному аудио (опц. num_speakers)
  → [4] faster-whisper: транскрибация всего файла нативно (language=ru, vad_filter=True);
        отмена проверяется между выдаваемыми сегментами
  → [5] Alignment: сопоставление сегментов со спикерами методом max-overlap (fallback UNKNOWN)
  → [6] Применение пользовательских имён спикеров (если заданы) + форматирование
  → Вывод: JSON + TXT + SRT + DOCX (в outputFolder); temp-файлы удаляются в finally
```

> **Важно (изменение относительно 1.x/2.0):** ручная нарезка на чанки по 300 сек **убрана**. Это
> был воркэраунд под `openai-whisper`, который загружал весь mel-спектр в память и не справлялся
> с длинными файлами. `faster-whisper` обрабатывает файл любой длины нативно (внутренние 30-сек
> окна + потоковый вывод сегментов), поэтому жёсткие срезы по словам каждые 5 минут больше не
> нужны и вредны для качества.

### 6.3 Параллелизм и ресурсы GPU

- В системе доступна **одна видеокарта** → очередь обрабатывает **один файл одновременно** (`concurrency = 1`). Параллельный запуск двух задач на одном GPU запрещён (риск OOM).
- Модели (Whisper + pyannote) загружаются один раз при старте сервера и живут в памяти; при смене модели — перезагрузка.
- Тяжёлые вызовы выполняются в `asyncio.to_thread`; отмена — кооперативная (флаг проверяется между сегментами/стадиями, не прерывает уже запущенный нативный вызов).

| Сторона | Зависимость | Назначение |

## 9. Критерии приёмки

- [ ] Приложение запускается на Windows 10/11 с NVIDIA GPU
- [ ] При отсутствии CUDA-GPU выводится понятное сообщение об ошибке (обработка не стартует)
- [ ] Drag-and-drop одного аудиофайла приводит к успешной транскрибации с диаризацией
- [ ] Длинный файл (1+ час) обрабатывается без ручного чанкинга и без обрывов слов на границах
- [ ] В результатах каждый сегмент имеет метку спикера (max-overlap) и таймстемп
- [ ] Переименование спикера в UI отражается во всех экспортируемых форматах
- [ ] Экспорт работает во всех 4 форматах (JSON, TXT, SRT, DOCX)
- [ ] Автообработка папки: появление нового файла → автоматическая транскрибация; результаты конвертации не вызывают повторную обработку
- [ ] После обработки в исходной/отслеживаемой папке не остаётся временных файлов (`*.wav`, промежуточный MP3)
- [ ] Одновременно выполняется не более одной GPU-задачи
- [ ] Backend недоступен без секрет-токена; CORS закрыт для посторонних origin
- [ ] Переключение тёмной/светлой темы работает без перезагрузки
- [ ] Русский интерфейс отображается корректно без кракозябр
- [ ] При отсутствии FFmpeg выводится понятное сообщение об ошибке
- [ ] HF-токен вводится в интерфейсе (без правки `.env`); при неверном токене — инструкция по получению

| Параметр | WhisperAnnote 1.x | WhisperAnnote 2.0 |
